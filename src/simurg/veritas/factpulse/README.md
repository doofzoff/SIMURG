# FactPulse — token-level fabrication signals with decoder logprobs

**Developed by doofZ (Farid Aghayev), HAL-X AI · part of SIMURG · Veritas.**

FactPulse is a token-level dataset for studying **when a language model's own
logprobs reveal that it is fabricating a fact** — and, importantly, **when they
do not**. Every row is one *fact-bearing token* (a number or a named entity) from
a model answer, stored together with the decoder's top-k next-token distribution
and the features derived from it (entropy, top1−top2 margin, competing
alternatives), plus a fabrication label.

## The headline finding (read this first)

> **77% of fabricated numbers are generated *confidently* (near-zero token
> entropy).** Single-generation logprobs cannot catch them.

Averaged over all fact tokens the signal looks real — fabricated numbers have
higher entropy (0.28 vs 0.001) and lower decisiveness margin (11.2 vs 17.8) than
confident ones. But that average is carried by a minority: **most fabrications
are confident confabulations that look, at the logprob level, identical to
confident recall.** By question type:

| fabrication type | share generated confidently (norm-entropy < 0.05) |
|---|---|
| future GDP figure | **98%** |
| over-precise population | 59% |
| obscure count | 85% |
| invented-person birth year | 50% |

**Consequence for detector design:** token-time uncertainty (Veritas Layer 2)
is a **high-precision but low-recall** catcher — when entropy *is* elevated on a
number, it is almost certainly a fabrication (confident numbers essentially never
show elevated entropy), so it fires rarely but reliably. Catching the confident
majority needs **self-consistency** (semantic entropy, Layer 3), **verification**
(Layer 4), or **grounding** (Layer 5). FactPulse exists to quantify exactly this
boundary.

## How it is built (distant supervision, no human labels)

Answers are generated by a self-hosted 12B model (`wahoo-1.5-preview`) with
`logprobs=true, top_logprobs=6`. Labels come from the *question class*:

- **KNOWN** questions (well-known capitals, famous birth years, atomic numbers,
  basic science) → the answer's fact tokens are confident recall → **label 0**.
- **UNANSWERABLE** questions (exact population of an obscure town on a specific
  date, a country's GDP growth in 2045, the birth year of a plausibly-named but
  invented scholar, over-precise trivia) → any specific *number* the model emits
  is a guess it cannot possibly know → **label 1** (only numeric tokens; entities
  in these answers, e.g. institution names, stay confident/0).

Split is **by question**, so no answer leaks across train/test.

## Schema (JSONL, one row per fact token)

```json
{"question": "...", "question_class": "known|fab", "gold": "...",
 "answer": "...", "token": " 3.5", "position": 0.62, "kind": "number|entity",
 "entropy": 0.34, "norm_entropy": 0.19, "margin": 0.20, "top1_prob": 0.71,
 "chosen_prob": 0.68, "competing_numbers": 2, "competing_entities": 0,
 "is_number": 1, "is_entity": 0, "top_alts": ["3.5","4.1","3.2"], "label": 1}
```

## Size

~1.5K fact tokens (902 number, 631 entity) over ~370 questions, ~80/20
train/test by question. Seed model: `wahoo-1.5-preview`. See `stats.json`.

## Load

```python
import json
rows = [json.loads(l) for l in open("factpulse_train.jsonl", encoding="utf-8")]
```

## Baseline

`python3 -m simurg.veritas.factpulse.train` fits a 6-feature logistic model on
the logprob features (no `is_number`/`is_entity` crutch) and reports held-out
AUROC plus the honest **within-number** AUROC that exposes the confident-
fabrication ceiling.

## Limitations

Distant supervision is noisy: a "known" question the model happens not to know
would be mislabeled confident, and an "unanswerable" number the model happens to
get right is still labeled fabricated (it had no basis to know it). Entity
fabrications are under-represented (models tend to refuse obviously fictional
entities). The confident-fabrication ceiling is the point, not a defect.
