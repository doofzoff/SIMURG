# Training the SIMURG Learned Tier

SIMURG works out of the box with its **rule tier alone** — training is optional.
The learned tier is a tiny online logistic regression (one weight per streaming
feature, 15 total) that adds robustness on top of the rules and enables
continual learning in production. This guide covers every way to (re)train it.

---

## 0. What exactly is trained

- **Model**: `simurg.model.OnlineLogReg` — 15 weights + bias over
  `StreamFeatures.VECTOR` (digit fraction, foreign-script fraction, repetition
  rate, compressibility, TTR, n-gram surprise statistics, SimHash drift, …).
- **Data unit**: *checkpoint vectors*. Every stream is replayed through the
  single-pass `StreamFeatures` state and snapshotted every 300 characters:
  - clean stream → all checkpoints labeled `0`;
  - corrupt stream → checkpoints **after** `onset + 250` labeled `1`,
    checkpoints **before** the onset labeled `0` (hard negatives from the same
    distribution), the boundary window skipped.
- **Loss**: logistic log-loss, plain SGD (`partial_fit`), seconds on a CPU.
- **Calibration**: after training, the conformal thresholds (`corrupt_at`,
  `suspect_at`) are re-derived from *clean-stream fused scores* — this is what
  gives the finite-sample false-alarm guarantee. Always recalibrate after
  retraining.

Artifacts: `weights/simurg_model.json` (weights) and `weights/simurg_calib.json` (thresholds).
`Simurg(...)` auto-loads the calibration file; the model is passed explicitly
(`Simurg(model=OnlineLogReg.load(...))`).

---

## 1. Quickest path — benchmark-train on CorruptBench

```bash
python3 -m simurg.data.evaluate --save
```

Builds the dataset (see §3 for corpus sources), trains 6 SGD epochs, calibrates
conformal thresholds on training-split clean streams (α = 0.02), prints the full
benchmark table (stream TPR/FPR, AUROC, per-class recall, detection latency,
onset error, zero-leak, throughput), and writes `weights/simurg_model.json` +
`weights/simurg_calib.json`.

## 2. Watchable path — the live training dashboard

```bash
python3 -m simurg.training.train_live          # trains on hf_dataset/corruptbench_*.jsonl
```

Runs the 4-phase pipeline (feature extraction → 40 SGD epochs → conformal
calibration → held-out stream evaluation) while writing `metrics.json` for the
bundled dashboard (`training/train_ui/index.html`): live log-loss (train/test), accuracy,
AUROC, **all 15 weights animating per epoch**, process memory, and the final
stream-level TPR/FPR verdict.

- Output dir: `$SIMURG_DASH_DIR` if set; otherwise a served web root when the
  host has one, else `simurg/train_ui/serve/` — serve it with
  `python3 -m http.server -d simurg/train_ui/serve 8080` and open
  `http://localhost:8080`.
- Epochs: `$SIMURG_EPOCHS` (default 40).
- Saves to `simurg_model_hf.json` / `simurg_calib_hf.json` so your production
  weights are never overwritten implicitly — swapping is a deliberate `cp`.

## 3. Training on YOUR data

Two knobs control the corpus:

**Clean negatives** — `simurg.dataset.load_clean_corpus`, in priority order:
1. `SIMURG_CORPUS_JSONL=/path/corpus.jsonl` — one JSON object per line with a
   `text` field. Use *your* domain's real clean outputs: they are the hardest
   negatives and the thresholds calibrate to them.
2. an optional deployment DB hook (skipped outside our deployment);
3. bundled fallback seeds (smoke tests only — do not ship a model trained on
   these alone).

**Corrupt positives** — generated by `simurg.synth.corrupt` at controlled
onsets. To synthesize a full dataset from any OpenAI-compatible model:

```bash
SIMURG_GEN_URL=http://localhost:8000/v1/chat/completions \
SIMURG_GEN_MODEL=your-model \
python3 -m simurg.data.generate_dataset
```

(edit `N_SEEDS`, languages, topics in the script header to taste; the split is
by seed text, so corrupt variants never leak across splits).

## 4. Online learning in production (the flywheel)

`OnlineLogReg.partial_fit` accepts single examples — the serving loop can be
the training loop:

```python
from simurg import OnlineLogReg, StreamFeatures

model = OnlineLogReg.load("weights/simurg_model.json")

# an aborted stream whose retry produced an accepted answer ⇒ confirmed positive
f = StreamFeatures(); f.feed(aborted_prefix_text)
model.partial_fit([f.vector()], [1])

# an operator "false alarm" click ⇒ confirmed negative
f = StreamFeatures(); f.feed(flagged_but_clean_text)
model.partial_fit([f.vector()], [0])

model.save("weights/simurg_model.json")
```

Recalibrate the conformal thresholds on your rolling clean-score sample on the
same schedule (`ConformalEnsemble.calibrate(clean_scores, alpha=0.02)`), so the
false-alarm guarantee tracks drift. We recommend gating automatic weight
updates behind an operator switch and keeping an audit trail of every update.

## 5. Sanity checklist after any retraining

1. `python3 -m simurg.data.evaluate` — stream TPR should stay 1.0-ish, FPR ≈ 0.
2. Replay the model over a sample of **real clean traffic** (post-hoc
   `check_text`-style loop) — the measured FPR on production text is the number
   that matters.
3. Inspect the weights: they should be interpretable (digit/structural/repeat
   positive, TTR/compressibility negative). A sign flip on a major feature
   means your corpus shifted — investigate before shipping.
4. Ship weights + calibration **as a pair**; never mix a new model with old
   thresholds.
